# Development and release

## Adding or changing a Skill

Use `skill-system-engineering` when changing Skill boundaries, descriptions, progressive loading, permissions, bundles, or provenance.

A top-level Skill should contain only the files it needs:

```text
SKILL.md                 concise trigger and execution contract
references/              conditional long-form guidance, when needed
scripts/                 deterministic operations, when needed
assets/                  reusable non-code inputs, when needed
agents/openai.yaml       Harness metadata
evals/evals.json         behavioral fixtures
LICENSE                   standalone license
```

Do not create empty directories. Keep the frontmatter name aligned with the directory and define positive and negative trigger boundaries.

## Unified tooling

Public repository operations use one cross-platform entry point:

```bash
python3 -m rops --help
```

The `rops/` package separates project setup, proposal logic, quality checks, and release packaging internally. Do not reintroduce many single-purpose root scripts or duplicate Bash/PowerShell implementations unless a platform cannot use Python.

## Harness compatibility

Framework paths live in `config/frameworks.json`. Shared roles are rendered into native Codex, Claude Code, and Gemini CLI files by the adaptive-agent Skill. Keep workflow prose shared rather than maintaining divergent framework copies.

## Third-party content

No third-party Skill is vendored by default. To add one, pin the exact commit, preserve its license, audit executable/network behavior, install only the needed subtree, and update `PROVENANCE.json`, README acknowledgements, security notes, and tests. `config/vendor-lock.example.json` documents the expected metadata.

## Generated files

Do not hand-edit:

- `catalog/README.md` and `catalog/skills.json`;
- `release/MANIFEST.sha256`;
- `release/VALIDATION.md`.

They are generated by the unified CLI.

## Required checks

```bash
python3 -m rops validate
python3 -m rops validate --smoke
python3 -m rops package --out /tmp/researchops-toolkit-release
```

The smoke test covers cross-framework installation, native Agent rendering, proposals, model routing and independent verification, archive/restore/purge, large-data quarantine, internal-ID normalization, worktree safety, dashboard validation, and core research-engineering utilities.

## Changelog policy

Record only user-visible release changes, deprecations, compatibility notes, and security changes. Do not use `CHANGELOG.md` as a commit log.
