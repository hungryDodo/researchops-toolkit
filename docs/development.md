# Development and release

## Decide which layer owns a change

Use this order:

1. **Universal invariant across nearly all tasks** → compact kernel rule.
2. **Cross-cutting behavior across multiple workflows** → Behavior Pack.
3. **User-recognizable procedure with its own artifact/acceptance contract** → top-level Skill or a mode of an existing Skill.
4. **Deterministic reusable state/tooling with no user routing intent** → internal component.
5. **Framework transport/schema only** → Hook or plugin adapter.

Do not turn a long workflow into an always-on Pack, and do not turn a one-line policy into another top-level Skill.

## Adding or changing a Skill

Use `skill-system-engineering` for Skill boundaries, descriptions, progressive loading, permissions, bundles, provenance, or Harness metadata.

```text
SKILL.md                 concise trigger and execution contract
references/              conditional long-form guidance
scripts/                 deterministic operations when needed
assets/                  reusable non-code inputs when needed
agents/openai.yaml       Harness metadata
evals/evals.json         behavioral fixtures
LICENSE                  standalone license
```

Keep positive and negative trigger boundaries and update `tests/trigger-cases.json` when discovery changes.

## Adding or changing a Behavior Pack

A Pack must be concise, cross-cutting, and independently testable. Update:

- `behavior/packs/<id>.json`;
- `behavior/registry.json`;
- `behavior/evals/cases.json`;
- `docs/behavior-runtime.md` when the public contract changes;
- `tests/behavior_smoke.py` for decision or adapter changes.

Keep deterministic parsing/policy decisions separate from semantic escalation. A semantic reviewer may add or increase risk, but must never remove a deterministic finding.

## Hook adapters

- Shared executable: `hooks/researchops_hook.py`.
- Plugin hook manifest: `hooks/claude-codex-hooks.json`.
- Gemini extension hook manifest: `hooks/hooks.json`; project-level Gemini settings are generated by `rops behavior install`.
- Claude marketplace metadata: `.claude-plugin/marketplace.json`.
- Project installer: `rops/behavior.py`.

Treat each platform's input/output schema as a strict external contract. Validate generated settings, lifecycle coverage, trust behavior, Windows/POSIX commands, enforce-mode fail-closed behavior, semantic-review failure modes, and platform permission fallbacks.

## Unified tooling

```bash
python3 -m rops --help
```

Do not reintroduce many root scripts or duplicate Bash/PowerShell implementations when the Python CLI can own the operation.

## Third-party content

No third-party implementation is vendored by default. To add one, pin the commit, preserve its license, audit executable/network behavior, install only the required subtree, and update `PROVENANCE.json`, README acknowledgements, security notes, and tests.

## Generated files

Do not hand-edit:

- `catalog/README.md` and `catalog/skills.json`;
- `release/MANIFEST.sha256`;
- `release/VALIDATION.md`.

## Required checks

```bash
python3 -m rops validate
python3 -m rops validate --smoke
python3 -m rops package --out /tmp/researchops-toolkit-release
```

The smoke suite covers Skills, Hook installation, Pack selection, parsed/canonical content-bound one-use approval, 131-case adversarial risk corpus, optional semantic escalation, metadata-only logging, sub-agent routing, archive/restore/purge, large-data quarantine, ID normalization, worktree safety, dashboard validation, and research-engineering utilities.

## Changelog policy

Record user-visible release changes, deprecations, compatibility notes, and security changes only. Do not use `CHANGELOG.md` as commit history.
